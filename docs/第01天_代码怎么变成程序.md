## 一、为什么要学这个 

### 1.1 ① 是什么：你在编辑器里存下的那个文件到底是什么

```text
你在编辑器里敲的字 → 保存 → days/day01_compile.c 躺在硬盘上

  它是**一串文本**：字母、数字、括号、分号、换行。
  长度上它和一篇 Word 文档没有区别。
```

现在做今天的第一件事，也是决定后面 13 天能不能学下去的第一件事：

```text
CPU 能不能读这个文件？   —— 不能。
```

CPU 里刻死的只有几十条指令：加、减、乘、比较、跳转、从某个地址读几个字节。
它不知道 'p' 是什么字符，更不知道 `printf` 这七个字母对应哪串数字。
**"语法""函数名""语句"这些概念对它统统不存在。**

### 1.2 ② 为什么需要它：如果没有"翻译官"会怎样

那就必须有一个程序，把文本翻译成 CPU 唯一认得的东西——机器指令。
这个翻译官叫**编译器**，你敲下 `gcc` 的那一刻它就开始干活了。

如果你只学过 Python，你可能会问："为什么不能直接跑？"
因为 Python 里有一层**运行时解释器**帮你做了同样的翻译，只是把它藏起来了。
C 是**编译型语言**：翻译必须在跑之前完成，翻译成功才有可执行文件。

这带来两个**后果**，你今天会当场遇到：

**后果一：你会遇到一种全新的错误类型 —— 编译错误。**
Python 写错函数名是运行时才报 `NameError`；C 写错函数名是**编译时**就报
`implicit declaration of function`，一个字节的机器码都生成不出来。

**后果二：你必须建立"代码 → 内存"的心智模型。**
Python 里 `a = [1,2,3]`，`a` 是什么？是一个指向列表对象的引用。
C 里 `int a[4]`，`a` 是什么？**是一块 16 字节内存的起始地址。**
没有这个心智模型，Day 2 的数组、Day 4 的指针、Day 8 的 mmap 全部讲不通。

### 1.3 ③ 为什么是这种形式：为什么必须是这四步

翻译这件事没法一步做完，因为它是**分层**的——每一层只关心自己那一层的细节：

```text
  预处理  →  编译  →  汇编  →  链接
  （展开）   （翻译）  （烧进）  （拼装）
```

比如"把 1+1 折成 2"这件事，只有在**语法已经检查通过之后**才敢做；
而"把 `printf` 的真实地址填进那条 call 指令"，必须等所有 `.o` 都拿到手、
才知道该填哪个地址。所以四步的顺序是死的，不是谁发明的，是被依赖关系逼出来的。

**为什么第一天必须先讲 gcc 四步？**
因为后面 13 天你报的每一个编译错误，都落在这四步里的某一步。
知道"我在第几步失败"，比背 20 条报错信息有用一百倍。

**为什么第一天必须把 `float` 占 4 字节算出来？**
因为 14 天后你要打开一个 59MB 的模型文件。那 59MB 从哪来的？
`15204000 个参数 × 4 字节 = 60,816,000 字节`。
今天你手算一遍，Day 5/Day 8 打开它的时候就知道该期待什么。

### 1.4 ⑤ 它在整体流程里的位置

```text
今天确立的两条东西会跟着你走完 14 天：
  · float 占 4 字节 → Day 8 起那 1520 万个权重参数就是它；
  · scanf 读变量要写 & → Day 4 才知道那个 & 是"地址"，Day 5 用它读文件头。
```

## 二、必备知识速查

### 编译命令（全程只用这一条）

```bash
gcc -O2 -std=c11 -Wall -o day01 days/day01_compile.c -lm
```

| 选项 | 作用 | 不写会怎样 |
|---|---|---|
| `-O2` | 开启二级优化 | 能跑但慢 5~10 倍 |
| `-std=c11` | 声明使用 C11 标准 | 可能因为"方言不同"报奇怪的错 |
| `-Wall` | 打开全部警告 | 小错误累积成大 bug，Day 4 排查痛苦十倍 |
| `-o day01` | 指定输出文件名 | 生成的叫 `a.out` |
| `-lm` | 链接数学库（放最后） | 用 `sqrtf` 时报 `undefined reference` |

### 八种基本类型

| 类型 | 占字节 | 取值范围（简） | 典型用途 |
|---|---|---|---|
| `char` | 1 | -128 ~ 127 | 单个字符 / 一个字节 |
| `short` | 2 | -32768 ~ 32767 | 短整数（省内存） |
| `int` | 4 | 约 ±21 亿 | 最常用整数 |
| `long` | 8 | 约 ±922 亿亿 | 时间戳 / 文件大小 |
| `float` | 4 | 约 ±3.4e38 | **大模型权重** |
| `double` | 8 | 约 ±1.7e308 | 更准但更慢的浮点 |
| `unsigned X` | 同上 | 0 ~ 上限 | 永远非负 |
| `void` | — | 无 | "无返回值"或"通用指针" |

### printf 格式符

| 格式符 | 用途 | 例子 → 输出 |
|---|---|---|
| `%d` | 十进制整数 | `printf("%d", 42)` → `42` |
| `%f` | 浮点（默认 6 位小数） | `printf("%f", 3.14159)` → `3.141590` |
| `%.2f` | 保留 2 位小数 | → `3.14` |
| `%e` | 科学计数法 | → `1.234568e+04` |
| `%c` | 单个字符 | `printf("%c", 'L')` → `L` |
| `%s` | 字符串 | → `hello` |
| `%x` | 十六进制 | `printf("%x", 255)` → `ff` |
| `%p` | 指针地址 | → `0x7ffd...` |
| `%zu` | `sizeof` 的结果 | → `4` |
| `%%` | 字面上的百分号 | `printf("100%%")` → `100%` |
| `%-10s` | 左对齐占 10 列 | → `[ab        ]` |
| `%10s` | 右对齐占 10 列 | → `[        ab]` |

### 程序骨架（背下来）

```c
#include <stdio.h>              /* 头文件：声明 printf/scanf 的存在 */

int main(void)                   /* 程序唯一入口 */
{
    int x = 10;                  /* 声明并初始化 */
    printf("x = %d\n", x);      /* 输出 */
    return 0;                    /* 0 = 正常结束 */
}
```

### 本课程两条硬性规范

```
1. 所有 scanf 必须检查返回值
   if (scanf("%d", &n) != 1) { printf("输入无效\n"); return; }

2. 不许用 const int 当数组长度（C 的 const 不是编译期常量，会变成 VLA）
   enum { N = 3, M = 4 };        ← 用 enum 拿编译期常量
   int a[N][M] = {{0}};          ← 合法
```

## 三、核心概念详解

### 3.1 gcc 四步流水线

**定义**：gcc 把一个 `.c` 文本变成 CPU 能执行的机器码，要走四道工序。

```
  day01_compile.c
       │
       │ ① 预处理 (Preprocess)        gcc -E
       │   · #include 的头文件内容"文本粘贴"进来
       │   · #define 宏替换
       │   · 所有注释被删掉
       ▼
  day01_compile.i        ← 一个巨大的 .c 文件，stdio.h 全文都在里面
       │
       │ ② 编译 (Compile)             gcc -S
       │   · 语法检查、类型检查
       │   · 优化：把 1+1 折成 2、把不变的循环提出来
       │   · 分配寄存器，生成汇编代码
       ▼
  day01_compile.s        ← x86 汇编
       │
       │ ③ 汇编 (Assemble)            gcc -c
       │   · 汇编代码 → 机器码
       ▼
  day01_compile.o        ← ELF 目标文件：机器码 + 重定位表 + 符号表
       │
       │ ④ 链接 (Link)                gcc -o
       │   · 把 .o 和库（libc、libm）拼在一起
       │   · 填好所有函数的实际地址
       ▼
  day01_compile          ← 可执行文件（Linux 下也是 ELF 格式）
```

**亲手验证**（这四条命令必须敲一遍）：

```bash
gcc -E days/day01_compile.c -o /tmp/s1.i && wc -l /tmp/s1.i          # 几万行，全是 stdio.h
gcc -S days/day01_compile.c -o /tmp/s2.s && head -20 /tmp/s2.s       # 开始看到 mov/add
gcc -c days/day01_compile.c -o /tmp/s3.o && file /tmp/s3.o           # ELF 64-bit relocatable
gcc    days/day01_compile.c -o /tmp/s4.bin -lm && file /tmp/s4.bin   # ELF 64-bit executable
```

**常见坑**：
- 以为"编译"是一步。报错里的 `ld returned 1 exit status` 说明你已经在**第 ④ 步**，前三步都过了。
- 混淆 `.o` 和可执行文件。`.o` 里的函数地址全是空的（只有符号表记着"我需要 printf"），
  必须链接才能填上真实地址。
- 把 `-lm` 放前面。链接器从左到右处理，先看到 `-lm` 还没有需要它的目标文件，
  就会报 `undefined reference to 'sqrtf'`。

### 3.2 `sizeof` 与内存布局

**定义**：`sizeof(类型)` 返回该类型占用的**字节数**，类型是 `size_t`（无符号长整型）。

**图示**：`int a[4] = {10, 20, 30, 40}` 在内存里长这样

```
  高地址
    ┌────────┐
    │  40    │  &a[3]   字节偏移 12
    ├────────┤
    │  30    │  &a[2]   字节偏移  8
    ├────────┤
    │  20    │  &a[1]   字节偏移  4
    ├────────┤
    │  10    │  &a[0]   字节偏移  0   ← a 指向这里
    └────────┘
  低地址        共 4 × 4 = 16 字节
```

**最小代码示例**：

```c
#include <stdio.h>
int main(void) {
    int a[4] = {10, 20, 30, 40};
    printf("sizeof(a)      = %zu\n", sizeof(a));            /* 16 */
    printf("sizeof(a)/sizeof(a[0]) = %zu\n",
           sizeof(a) / sizeof(a[0]));                       /* 4 */
    for (int i = 0; i < 4; i++) {
        long off = (long)((&a[i] - &a[0]) * sizeof(int));
        printf("a[%d] @ %p 偏移 %ld 字节\n", i, (void *)&a[i], off);
    }
    return 0;
}
```

**两条必须背下来的结论**：

```
相邻元素地址差 = sizeof(元素类型) = 4 字节
第 i 个元素的字节偏移 = i * 4
```

**常见坑**：
- 用 `%d` 打印 `sizeof` 的结果。`sizeof` 返回 `size_t`（64 位无符号），
  必须用 `%zu`，否则 `-Wformat` 报警告。
- 以为 `&a[i] - &a[0]` 得到的是字节数。它得到的是**元素个数**，
  C 的指针算术单位是"元素"，不是"字节"。

### 3.3 `scanf` 为什么必须写 `&`

**定义**：`scanf` 干的事是"把键盘上的字符变成数值，写进内存"。
要写入内存，它必须知道**写到哪里** —— 也就是需要一个地址。

```
  正确：  int  n;   scanf("%d", &n);
                    ↑ & 取出 n 的地址，scanf 拿到地址才能写

  错误：  int  n;   scanf("%d", n);
                    ↑ 传的是 n 的"值"（比如 0），scanf 会往地址 0 写
                      → Segmentation fault (core dumped)

  可以不写 &： char s[20];  scanf("%s", s);
                      ↑ 数组名本身就等于首元素地址
```

**图示**：两个变量的内存图

```
   栈                                  栈
  ┌──────────┐                      ┌──────────┐
  │ n  = 10  │ @0x7ffdA0            │ n  = 10  │ @0x7ffdA0
  └─────▲────┘                      └──────────┘
        │                                  ▲
   &n 就是这个地址                    &n  也是这个地址
```

**常见坑**：
- **忽略返回值**。`scanf` 返回成功读入的变量个数。输入 "abc" 时返回 0，
  目标变量保持原值（本课程规范是初值 0）。忽略它 gcc 会报
  `warning: ignoring return value of 'scanf'`，而这个警告背后是真 bug：
  高度还是 0，你拿它去除法，直接崩。
- **EOF 死循环**。用管道喂输入时最后会读到 EOF（返回 -1），
  如果你在 `for(;;)` 菜单里写 `if (scanf(...) != 1) continue;`，
  就会永远空转。正确做法是**分辨 0 和 EOF**：

```c
int got = scanf("%d", &q);
if (got == EOF) return 0;              /* 输入流结束 → 退出程序 */
if (got != 1) { /* 丢掉这一行脏数据，再问一次 */ continue; }
```

### 3.4 三种分支结构

**定义**：C 只有两种分支关键字 —— `if` 和 `switch`。

```
① if / else if / else      适合"按范围判断"

     if      (bmi < 18.5f)  printf("偏瘦\n");
     else if (bmi < 24.0f)  printf("正常\n");
     else                  printf("偏胖\n");

     从上往下判断，一旦命中一个分支，后面的分支都不再执行。
     ★ 边界值用 < 而不是 <=，否则 BMI 恰好 24.0 会落进两个分支。

② switch / case / default   适合"等于若干固定值之一"

     switch (score / 10) {
     case 10:              /* 故意不 break，和下一个 case 共用代码 */
     case  9: printf("A\n"); break;
     case  8: printf("B\n"); break;
     default: printf("F\n"); break;   /* 兜底，防所有 case 都不匹配 */
     }
```

**执行流程图**：

```
        score / 10
              │
    ┌─────────┼─────────┬─────────┐
   10,9       8         7,6      其它
    │         │         │         │
  "A"       "B"       "D"      default
    │ break   │ break   │ break     │
    └─────────┴─────────┴─────────┴──► 跳出 switch
```

**常见坑**：
- **漏写 `break`（贯穿 fall-through）**。程序会一路执行下一个 `case` 的语句，一个不落。
  今天的成绩等级故意用了它（`case 10` 和 `case 9` 共用"优秀"），
  但其他 4 个 case 末尾都必须有 `break`。
- **`switch` 里比较的是"整除后的值"**。`switch (score)` 写 100 个 case 是傻办法，
  写 `switch (score / 10)` 才聪明。
- **把区间判断塞进 `switch`**。`case 1 ... 5`（范围 case）是 C23 才有的，
  C11 里只能老老实实用 `if`。

### 3.5 `if/else` + 循环 = 第一个完整程序

**定义**：`if/else` 负责"分岔"，循环负责"重复"。两者组合就能写出有交互的程序：

```
  ┌──────────────────────────┐
  │ while (还有机会)         │  ← 循环：重复问
  │   读入 guess             │
  │   if (guess == secret)   │  ← 分支：三种结局
  │       猜中 → break       │
  │   else if (太小) 提示    │
  │   else           提示    │
  └──────────────────────────┘
```

**必须做的防御**：`scanf` 失败时**必须 `break`**，否则循环变量不增加、程序假死。

```c
while (attempts < max_attempts) {
    int guess = 0;
    if (scanf("%d", &guess) != 1) break;   /* 不 break 就死循环 */
    attempts++;
    if (guess < secret)      printf("太小\n");
    else if (guess > secret) printf("太大\n");
    else { printf("猜中\n"); break; }
}
```

### `demo_types()`：八种类型 + sizeof + 内存布局

**解决什么问题**：建立"类型 = 内存格子数量"的直觉。关键三行：

```c
printf("  void* 指针   占 %zu 字节\n", sizeof(void *));   /* 8 —— 指针本身也是值 */
for (int i = 0; i < 4; i++) {
    long offset = (long)((&a[i] - &a[0]) * sizeof(int));  /* ★ 元素差 → 字节差 */
    printf("a[%d] @ %p 偏移 %ld\n", i, (void *)&a[i], offset);

printf("15000000 × %zu ≈ %zu MB\n", sizeof(float), 15000000UL * sizeof(float)/1024/1024);
```

`(long)` 是把指针差强转成 `long`，好让 `%ld` 正确打印。写 `%td` 也对，但初学者看到 `td` 会懵。

### `demo_table()`：printf 宽度控制

**解决什么问题**：Day 13 要打印 32000 个 token 的分数，列对不齐根本没法看。
**关键点**：表头和数据行**必须用同一套宽度串**。表头写 `%-4s` 而数据行写 `%-6d`，
这一列就会错开两格。另外中文字符在等宽终端里占 2 个显示宽度，写中文表头要手动补偿。

### `demo_bmi()`：if / else if / else

**解决什么问题**：演示"按区间判断"的标准写法 + 养成检查 `scanf` 返回值的习惯。

```c
if (scanf("%f %f", &height, &weight) != 2) {   /* ★ 检查返回值 */
    printf("  输入无效，需要两个数字。\n");
    return;                                    /* 提前返回，别带着 0 往下算 */
}
if (height <= 0.0f) {                          /* ★ 防御性检查：防除以 0 */
    printf("  身高必须为正数。\n");
    return;
}
float bmi = weight / (height * height);
```

**为什么两次检查都要 `return`**：一次防"没读到数"，一次防"读到 0"。
凡是除法，先问自己"分母会不会是 0"。

### `demo_switch()`：switch / case / default / break

**解决什么问题**：把 11 种原始分数压成 6 个分支。

```c
switch (score / 10) {
case 10:
case 9:                       /* 贯穿：90 分和 100 分共用"优秀" */
    printf("  等级：优秀 (A)\n");
    break;                    /* ★ 每个 case 末尾的 break 都不能少 */
...
default:                       /* 兜底，挡住负分和 0 分 */
    printf("  等级：不及格 (F)\n");
    break;
}
```

### `demo_guess()`：if/else + 循环 + break

**解决什么问题**：把"重复"和"分岔"拼在一起，得到写程序的最小完整形态。
答案固定为 42（用常量代替随机数），保证课堂上可复现 —— Day 13 才引入 RNG。

## 常见错误

### 1. 漏写分号

```
day01_compile.c: 在函数 'demo_bmi' 中：
error: expected ';' before '}' token
```

**原因**：上一行末尾少了 `;`。
**排查方法**：gcc 报的错在**下一行**，真正的错误在**上一行**末尾。
养成习惯：写完一行先找分号。

### 2. 忘了写 `#include <stdio.h>`

```
warning: implicit declaration of function 'printf'
```

**原因**：没有声明 `printf` 的存在。默认按 `int printf()` 处理，返回值类型判断可能出错。
**解决**：加上 `#include <stdio.h>`。

### 3. `scanf` 少写 `&` → 段错误

```
Segmentation fault (core dumped)
```

**原因**：`scanf` 需要地址才能写入。传了值就等于往地址 0 写。
**解决**：`scanf("%d", &n)`。数组参数可以不加（`char s[20]; scanf("%s", s);`）。

### 4. 忽略 `scanf` 返回值

```
warning: ignoring return value of 'scanf' [-Wunused-result]
```

**原因**：用户可能直接按回车，或者输入了字母，`scanf` 返回 0，目标变量保持原值。
**解决**：`if (scanf(...) != 1) { 提示并 return; }`。
特别地：管道输入走到末尾会返回 `EOF`，在 `for(;;)` 菜单里必须靠 `EOF` 跳出循环。

### 5. 格式符和实参类型对不上

```
warning: format '%d' expects argument of type 'int', but argument has type 'double'
```

**现象**：打印出一串垃圾数字。
**修法**：整型 `%d/%i/%x`、浮点 `%f/%e`、`size_t` 用 `%zu`、指针用 `%p`。
另外 `sizeof` 的结果千万不要用 `%d` 打印。

### 6. 循环里的 `int i` 作用域

**现象**：在 `for (int i = 0; ...)` 外面用 `i`，编译报错。
**原因**：C99 之后 `for` 里声明的变量**只在 for 内部有效**。
**解决**：需要在循环外用就在外面声明 `int i;`。

### 7. 忘了 `-Wall` 让小错变大错

**现象**：Day 3 才开始调试"为什么我的值莫名变了"。
**原因**：第一天的漏分号/类型不匹配/未初始化变量，全都只发警告。
**解决**：编译命令里 `-Wall` 不是可选项。**零警告是验收标准，不是建议。**
